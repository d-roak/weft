# Use case: x402 payments

[x402](https://x402.org) is a way to make requests *machine-payable*: it revives
HTTP status **402 Payment Required** so a server can answer an unpaid request
with "here's the price and where to pay", the client pays, attaches proof, and
retries. weft carries that same handshake over its P2P channel, so agents can
charge each other with no accounts, invoices, or middlemen.

## Why agents want this

- **Paid relaying** — a node with great connectivity sells relay/forwarding hops
  to nodes that need them, metered per request.
- **API / service discovery** — a service discovered on the fabric advertises a
  `price` in its announcement; consumers pay per call to use it.
- **Any capability** — inference, data feeds, compute, tool calls: price them
  and let other agents pay programmatically.

Because payment settles to an address (e.g. a stablecoin transfer), there's no
signup — an agent that can sign a payment can consume a service instantly.

## The handshake

Three agent messages ([src/x402.rs](../../crates/weft/src/x402.rs)):

```
client                                   server
  │  invoke (no payment)                   │
  │ ─────────────────────────────────────► │
  │        402 payment-required            │   { price, nonce, resource }
  │ ◄───────────────────────────────────── │
  │  invoke  { …, payment: {scheme,        │
  │            nonce, proof} }              │
  │ ─────────────────────────────────────► │
  │                result                  │   verify → serve
  │ ◄───────────────────────────────────── │
```

- **`PaymentRequired`** — `{ price: PriceTag, nonce, resource }`. The `nonce`
  is single-use and binds the payment to this exact request (anti-replay).
- **`PriceTag`** — `{ amount, asset, network, pay_to, scheme }`, e.g.
  `1000 USDC` on `base-sepolia` to an address, scheme `exact` (the x402 default).
- **`PaymentPayload`** — `{ scheme, nonce, proof }`, attached on the retry.
  `proof` is the scheme-specific settlement artifact (a signed authorization or
  transaction).

Advertising the price up front, in discovery, lets a consumer decide *before*
connecting:

```rust
weft.registry().announce_full(ServiceAnnouncement {
    endpoint_id: weft.id(),
    name: "premium-relay".into(),
    kind: "relay".into(),
    meta: serde_json::json!({ "desc": "one forwarded message per paid request" }),
    price: Some(PriceTag::new(1000, "USDC", "base-sepolia", "0xYourWallet")),
}).await?;
```

## Runnable example

[`examples/x402_relay.rs`](../../crates/weft/examples/x402_relay.rs):

```bash
cargo run --example x402_relay -- server         # prints the server id
cargo run --example x402_relay -- client <id>
#   402: pay 1000 USDC on base-sepolia to 0xF00D…
#   → result {"ok":true,"relayed":"ship it"}
```

The first call comes back `402`; the client pays and the retry succeeds.

## Wiring real money

Verification and settlement live behind **one function**,
`x402::verify_payment`. The shipped version is a stub: it checks the scheme and
nonce match and that a proof is present — enough to exercise the full handshake
in tests and examples.

To accept real payments, replace its body with a call to an x402 **facilitator**
(the verify/settle service defined by the x402 spec): submit or verify the
on-chain payment authorization, confirm the amount/asset/recipient match the
`PriceTag`, and return `true` only on success. Everything around it — the
handshake, nonces, the discovery price tag — stays as is.

Server-side checklist for production:

- Issue a **fresh nonce per request** and store issued/spent nonces so a proof
  can't be replayed. (The example uses a fixed nonce for brevity — marked with a
  `ponytail:` note.)
- Verify `amount`, `asset`, `network`, and `pay_to` in the proof match what you
  advertised, not just that *a* payment exists.
- Treat verification failures as `error` replies and don't serve.
